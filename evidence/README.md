# Verification evidence

The files in this directory record the English WeekPantry deployment and tests.
Screenshots are generated by the real browser smoke test. No passwords,
Secret contents, kubeconfig or database exports are included.

## English application lab

- Multipass VM: `nanofaas-stack`, existing k3s cluster, ARM64.
- Namespace: `weekpantry`, independently deployed from this repository.
- URL: <http://10.83.80.138:30189> (local lab network; not a public hosted service).
- NodePort override: `NODE_PORT=30189`; the default manifest uses `30188`.
- Reused control-plane image: see [control-plane-values.yaml](control-plane-values.yaml).

Inspect it without changing your local kubectl context:

```bash
multipass exec nanofaas-stack -- sudo k3s kubectl -n weekpantry get pods
```

The exact image tags, Ready pod states and a frontend execution trace are in
[deployment.json](deployment.json). Test results are recorded in
[tests-python312.txt](tests-python312.txt), [browser-results.json](browser-results.json)
and [persistence-results.json](persistence-results.json).

## Initial experiment

[initial-dispensa/](initial-dispensa/) preserves the evidence captured before
repository extraction. Pod names, image references and execution IDs remain
unchanged because these are observations from the original deployment.
Its screenshots intentionally show the original Italian UI; the screenshots
in this directory show the translated application.

The original `dispensa` namespace, URL on port `30188` and its data were not
deleted or migrated. Its Italian schema is separate from WeekPantry's English
schema. The image-specific resource catalog failure is recorded in
[initial-dispensa/resource-catalog-failure.txt](initial-dispensa/resource-catalog-failure.txt).
